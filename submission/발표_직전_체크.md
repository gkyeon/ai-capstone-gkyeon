# 발표 직전 체크

## 준비
- 최종 파일: `AI_Capstone_발표.pptx` 또는 같은 이름의 PDF.
- 대본: `발표대본.md`. 9장, 목표 4분 45초 + 여유 15초. 실제 발화 시간은 미측정.
- 준비시간 포함 최대 6분이므로 파일을 미리 열어 둔다. 현장 실시간 시연 대신 준비한 캡처로 설명해도 된다.

## 리허설 기준
1. 첫 문장은 “잘못된 수치를 믿고 운영 조치를 하는 위험을 줄이려고 개선했습니다.”
2. 2분 안에 4번 기술 설명까지 마친다. 약어를 나열하는 대신 역할을 설명한다.
3. 3분 10초 안에 6번 전후 화면 설명을 마친다.
4. 4분이 넘으면 8번은 “근거가 없으면 작성 호출을 생략했습니다”만 말하고 넘어간다.
5. 마지막에 “검사 통과는 답변 전체가 사실이라는 보장이 아닙니다”를 꼭 말한다.

## 예상 질문과 짧은 답변

**왜 검증을 중심으로 골랐나요?**
운영 진단은 그럴듯한 답변보다 수집 자료와 맞는 답변이 중요하다고 봤습니다. 확인 가능한 수치를 좁은 범위로 검증하고, 실패하면 멈추도록 했습니다.

**오류 차단 100%면 믿고 써도 되나요?**
아닙니다. 자체 평가셋에서의 결과입니다. 실제로 추가 사례에서 다른 오류를 발견해 고쳤습니다. 새 표현이나 원인 설명은 놓칠 수 있습니다.

**멀티에이전트인가요?**
모니터링과 매뉴얼을 담당하는 두 LangGraph 서브그래프로 분리했습니다. 독립 모델끼리 추론하거나 협상하는 구조는 아닙니다. 역할 분리와 테스트 편의가 목적입니다.

**왜 규칙으로 검증했나요?**
시스템명과 CPU·메모리는 수집값과 직접 비교할 수 있어 실패 이유가 명확하고 재현이 쉽습니다. 대신 자유로운 표현에는 약하므로 독립 평가와 다른 검증 방식 보완이 필요합니다.

**빨라졌고 비용도 줄었나요?**
일반 실모델 응답의 속도 향상은 주장하지 않습니다. 근거 없는 단일 질문에서 작성 호출을 생략하는 효과는 확인했습니다. 모델 분리 비용은 가정 단가에 따른 추정이며 실과금이 아닙니다.
