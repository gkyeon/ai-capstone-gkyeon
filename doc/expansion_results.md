# 검색·조사 안정성·화면 확장 결과

## 선택 이유
1. 기존 매뉴얼 선택 함수는 한국어 알림 3개를 모두 db-down 기본값으로 분류했다. 의미 기반 검색으로 증상 표현 차이를 처리한다.
2. 기존 병렬 조사에서 한 도구의 영구 오류가 전체 결과 반환을 막았다. 작업별 실패를 격리해 성공한 자료를 보존한다.

## 추가 구현
- qwen3-embedding:0.6b 로컬 임베딩 + 6개 매뉴얼의 코사인 유사도 검색. MCP 도구로 노출하여 검색된 문서를 답변 생성에 전달한다.
- 문서 내용·모델명이 바뀌면 인덱스를 다시 만들고 그 외에는 메모리 캐시를 재사용한다. 6개 짧은 문서라 외부 벡터 DB와 청크 분할은 도입하지 않았다.
- 최소 점수 0.45와 상위 두 후보 차이 0.025를 설계값으로 사용한다. 보정된 확률이 아니며 최적 기준을 입증하지 않았다. 미달 시 매뉴얼 미확정.
- RETRIEVAL_MODE=legacy|semantic 비교 설정. semantic이 기본. 검색 실패를 기존 db-down으로 몰래 대체하지 않는다.
- 작업별 예외 격리, 모니터링 호출 전체 15초 제한, 검색 호출 60초 제한. 성공 자료 보존과 실패 대상 안내. unknown 모니터링 기본값 0은 근거로 수집하지 않는다.
- 매뉴얼 추가 조사 한도를 넘겨도 충분하다고 표시하지 않고 부족 상태로 작성 단계에 넘긴다.
- 새 반응형 화면: 예시 질문, 진행 단계, 최종 답변, 수치 비교표, 검색 후보·점수, 검증 범위.

## 검증 결과
- 새 고정 사례 14개(장애 12개·무관 질문 2개): 기대 판정 일치 기존 6/14 → 의미 검색 12/14.
- 장애 질문만: 기존 6/12 → 의미 검색 10/12. 무관 질문은 2/2 미선택.
- 남은 두 사례: 커넥션 풀 질문은 상위 후보 차이가 작아 미확정, 연결 시간 초과 질문은 high-latency로 오선택.
- 이 평가는 같은 문자열을 기존 분류기의 모니터링 알림과 새 검색기에 전달한 구성요소 비교다. 실제 서비스 전체 정확도나 독립 평가 결과가 아니다. 새 검색을 고려해 작성한 소규모 자체 평가이며 임계값은 결과 확인 후 수정하지 않았다.
- 모의 도구 테스트: 일부 실패·전체 실패·자료 탐색 실패 격리 및 3개 전체 그래프 시나리오 통과. 인덱스 캐시 갱신·빈 자료 처리 확인.
- 기존 검증기 테스트 유지: 정상 7/8 통과, 오류 9/9 차단.
- 실제 로컬 서버 + MCP + 실제 임베딩 모델 + 모의 답변 모델로 최종 실행 확인. 실시간 진행, 검색 근거, 최종 비교표, 초안 미노출 확인.
- 데스크톱 1440px·모바일 390px 화면 테스트: 페이지 오류 없음, 모바일 가로 넘침 없음.

## 한계
실제 답변 모델(Ollama 생성 모델/OpenAI)의 이번 확장 후 검증은 아직 안 했다. 의미 검색이 항상 맞지 않으며 질의와 모니터링 알림이 충돌하면 잘못된 매뉴얼을 선택할 수 있다. 검색 인덱스는 메모리 캐시라 프로세스 재시작 시 재계산한다. 도구 연결의 기존 전역 잠금 때문에 병렬 작업 구성이 도구 호출 자체의 완전한 동시 처리를 뜻하지는 않는다. 원인 설명의 진실성을 검증하지 않는다.
