# 운영 장애 진단 에이전트 — 근거 기반 검증·검색·조사 안정성 개선

AI Capstone 개인과제. 수업에서 제공받은 **Base AI Agent**(운영 장애 진단: FastAPI + LangGraph + MCP + Vue)를 개선했다.
수집한 모니터링 자료와 답변을 대조해 틀린 답변을 막고, 매뉴얼을 의미로 검색하고, 일부 조사가 실패해도 확보한 자료로 진행하며, 그 근거를 화면에서 보여준다.

## 이 저장소에 담긴 것 / 담기지 않은 것

수업 제공 코드와 문서(기본 프로젝트, 매뉴얼, 실행 스크립트, 샘플 데이터 등)는 **공개할 수 없어 포함하지 않았다.** 그래서 **이 저장소만으로는 에이전트가 실행되지 않는다.** 아래만 담았다.

| 담음 (직접 만든 것) | 위치 |
|---|---|
| 근거 대조 검증기 | `agent/verifier.py` |
| 대상 시스템 해석 | `agent/targets.py` |
| 조사 서브에이전트(LangGraph 서브그래프) | `agent/subagents.py` |
| 임베딩 의미 검색 | `agent/retrieval.py` |
| 근거 점검 노드(근거 0건이면 작성 모델 호출 생략) | `agent/nodes/evidence_gate.py` |
| 테스트·평가·측정 스크립트와 결과 | `eval/` |
| 설계 결정 기록(ADR 15개), 체크리스트, 검증 설명 | `doc/` |
| 결과보고서, 발표 PPT/PDF, 대본, 화면 캡처 | `submission/` |

| 담지 않음 | 이유 |
|---|---|
| 수업 제공 원본 파일(`sh/`, `data/`, `mcp_client.py`, `retry.py` 등) | 공개 불가 |
| 원본을 수정해 만든 파일(`server.py`, `mcp_server.py`, `graph.py`, `web_chat.html`, LLM 모듈, `agent/nodes/` 대부분) | 원본 코드가 섞여 있어 공개 불가. 변경 내용은 보고서·ADR에 설명 |

## 기본 기능 vs 개선 사항

**기본 기능(제공받은 것)**: LangGraph 흐름(`route → plan → gate → research → replan_check → analysis → write → validate → finalize`), MCP 서버(모니터링 도구·매뉴얼·프롬프트), FastAPI·SSE·SQLite 세션, Vue 화면, 병렬 조사와 재시도, fast/quality 모델 분리, LangSmith 추적 코드. 검증은 "30자 이상 + `1)` 포함이면 통과, 3회 불합격하면 강제 합격", 매뉴얼은 키워드 규칙(못 찾으면 `db-down`)이었다.

| # | 기본 기능의 문제 | 개선 (직접 변경) | 효과 | 코드 위치 |
|---|---|---|---|---|
| ① | 형식만 검사해서 **틀린 수치도 통과**, 3회 실패는 강제 합격 | 시스템명·CPU·메모리를 수집값과 대조, 불일치 사유로 재작성, 실패하면 "검증 실패" 안내 | 오류 차단 2/9 → 9/9 | `agent/verifier.py` (연결 노드는 미포함) |
| ② | 검증기가 표현에 약함 | 동의어·숫자 먼저·표·'각각'·영어 서술 지원, 임계치·조건문·부정 수치 제외 | 표적 28개: 오류 차단 6/14 → 14/14, 정상 7/14 → 14/14 (자체 사례) | `agent/verifier.py` |
| ③ | 키워드로 매뉴얼 선택 | 로컬 임베딩 **의미 검색**, 점수가 낮거나 차이가 작으면 미확정 | 기대 일치 6/14 → 12/14 | `agent/retrieval.py` (MCP 도구 연결은 미포함) |
| ④ | 조사 하나가 실패하면 성공한 자료까지 버림 | 작업별 실패 격리, 시간 제한, 실패 대상 표시 | 부분 자료로 진행 + 한계 표시 | `agent/subagents.py` 외(미포함) |
| ⑤ | research 한 함수가 모든 조사를 처리 | monitoring/runbook **서브에이전트**로 분리, research는 supervisor | 구조 정리(성능 이득 없음) | `agent/subagents.py` |
| ⑥ | 없는 시스템을 **몰래 auth-service로 바꿔 조사** | 바꾸지 않고 조사 실패로 안내, 이름이 없을 때만 기본값을 쓰되 알림 | 묻지 않은 시스템 답변 방지 | `agent/targets.py` |
| ⑦ | 근거가 없어도 비싼 작성 모델 호출 | 모니터링 근거 0건이면 작성 생략 → "자료 부족" | 36.6초 → 1.2~2.7초 (단일 질문) | `agent/nodes/evidence_gate.py` |
| ⑧ | 한 파일에 모든 노드 | `state.py` + `nodes/` 6개 모듈로 분리 | 구조 정리 | (미포함) |
| ⑨ | 반려될 초안이 화면에 남을 수 있고 근거가 안 보임 | 초안 차단, 근거 비교표·검색 후보·검증 범위 표시 | 화면에서 근거 확인 | `submission/` 캡처 참고 |

**측정만 한 것(직접 구현이 아님)**: 병렬 vs 직렬 조사 약 3배(원본의 0.35초/태스크 시뮬레이션 지연 포함), fast/quality 모델 분리 약 59% 절감 추정(글자수 기반·가정 단가), 임베딩 도입의 대가(웜 검색 약 29ms, 모델 639MB).

## 테스트·평가 재현
`eval/`의 스크립트는 수업 제공 기본 프로젝트(그래프·MCP 서버·데이터)를 필요로 한다. **기본 프로젝트의 `agent/`·`data/`가 같은 위치에 있고 이 저장소의 파일이 덮어써진 환경**에서 프로젝트 루트에서 실행한다.
```bash
bash eval/run_tests.sh                     # 테스트 6종 + 검증 평가
.venv/bin/python eval/eval_verifier_v2.py  # 검증기 개선 전후 (기준선: eval/baseline/)
.venv/bin/python eval/eval_targets.py      # 대상 시스템 해석 전후
```
평가 결과 파일(`eval/*-20261021.*`, `eval/results.md`)은 실행 결과 그대로 올려 두었다. 결과를 읽기 위한 설명은 보고서 5절에 있다.

## 한계 (요약)
- 검증은 시스템명·CPU·메모리 **수치의 일치**만 확인한다. 원인 설명의 사실 여부는 판정하지 않는다. 규칙 기반이라 새 표현을 놓칠 수 있다.
- 수치-시스템 연결은 "직전에 나온 시스템명" 규칙이라, 미조회 시스템 설명 뒤에 다른 시스템의 수치가 오면 정직한 서술도 반려할 수 있다. 시스템 이름 꼴 규칙은 `customer-service`·`top-10` 같은 일반 표현을 시스템으로 오인한다.
- 평가는 소규모 자체 데이터이고 실모델은 질문당 한 번씩만 돌렸다. OpenAI 실모델과 LangSmith 기반 비교 평가는 하지 않았다.
- 서브에이전트는 LLM 판단 없이 도구를 호출하는 작업자이며 성능 이득은 없다.
- 초안 비공개를 위해 토큰 단위 스트리밍을 포기했다. 시스템명 요구를 완화한 대가로 수치 없는 답변은 대조 없이 통과한다.

자세한 한계와 트레이드오프는 [`submission/결과보고서.md`](submission/결과보고서.md) 6절과 [`doc/ADR.md`](doc/ADR.md).
